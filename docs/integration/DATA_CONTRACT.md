**Repository:** `adaptive-upi-fraud-detection`

**Status:** Canonical Data Contract Specification  
**Auditor:** Senior Software & Research Integration Engineer

---

## 1. Executive Summary & Core Rules

This document establishes the authoritative data contracts, wire schemas, serialization formats, and field classifications across every stage of the pipeline.

### Absolute Safety Rules on Ground Truth Labels:
1. **Label Isolation:** Any ground truth label (such as `isFraud`, `is_fraud`, `fraud_bool`, `Class`) is strictly **EVALUATION-ONLY METADATA**.
2. **Never an ML Input:** A ground truth label must **NEVER** be passed as an input feature into any model scoring function, online inference engine, or real-time feature vector.
3. **No Target Leakage in History:** In online streaming, real-time events do NOT possess immediate ground truth fraud confirmation. Any historical aggregation feature summing `isFraud` (e.g. `card_fraud_count_before`) is strictly an offline historical analysis feature and cannot be used for zero-latency online scoring.

## 2. Four-Tier Field Classification Hierarchy

Every field across the pipeline belongs to exactly one of the following four tiers:

```
┌────────────────────────────────────────────────────────────────────────┐
│ 1. EVENT DATA                                                          │
│    Raw, immutable attributes arriving from the client or payment rail. │
│    Examples: transaction_id, card_id, amount, event_time, merchant_id. │
├────────────────────────────────────────────────────────────────────────┤
│ 2. PROCESSING & VELOCITY FEATURES                                      │
│    Derived behavioral metrics computed in real-time or batch windows.  │
│    Examples: transaction_count_5m, total_amount_10m, velocity_ratio.   │
├────────────────────────────────────────────────────────────────────────┤
│ 3. GROUND-TRUTH LABELS (Evaluation Only)                               │
│    Historical target labels used strictly for offline validation.      │
│    Examples: isFraud, is_fraud, fraud_bool.                            │
├────────────────────────────────────────────────────────────────────────┤
│ 4. EVALUATION & INFERENCE OUTPUTS                                      │
│    Predictions and verdicts generated by models and decision engines.  │
│    Examples: fraud_probability, risk_score, decision (APPROVED/BLOCKED)│
└────────────────────────────────────────────────────────────────────────┘
```

## 4. Kafka Message Wire Contracts

### 4.1 Topic: `fraud-transactions` (Ingestion Wire Format)

- **Topic Name:** `fraud-transactions` (aliases for benchmarks: `transactions`, `ieee_cis_transactions`)
- **Partition Count:** 6 (scaled to 3 or 12 in benchmarks)
- **Replication Factor:** 1 (local dev) / 3 (KRaft cluster)
- **Message Key:**
  - **Type:** String (UTF-8)
  - **Content:** Entity Identifier (`card_id` or `user_id`, e.g. `"CARD-13926"` or `"USER042"`)
  - **Partitioning Guarantees:** Murmur2 hash ensures strict per-entity chronological ordering and zero cross-partition reordering.
- **Message Value:** Serialized JSON (UTF-8 encoded byte array)

#### Canonical Wire Schema:

| Field Name | Type | Tier | Required? | Description | Example |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `transaction_id` | String | Event Data | **YES** | Unique transaction identifier | `"TX-2987000"` |
| `card_id` | String | Event Data | **YES** | Primary entity partition key | `"CARD-13926"` |
| `user_id` | String | Event Data | Optional | User account identifier | `"USER042"` |
| `amount` | Float | Event Data | **YES** | Transaction payment amount (USD/INR) | `125.50` |
| `event_time` | String / Long | Event Data | **YES** | Event timestamp (ISO-8601 or epoch ms) | `"2026-10-05T14:30:00Z"` |
| `merchant_id` | String | Event Data | Optional | Merchant category or ID | `"M-W"` |
| `device_type` | String | Event Data | Optional | Client device (`mobile`, `web`) | `"mobile"` |
| `country` | String | Event Data | Optional | Country code or location | `"US"` |
| `dataset_source` | String | Event Data | Optional | Origin dataset identifier | `"ieee_cis"` |
| `is_fraud` / `isFraud` | Integer/Bool | **Ground-Truth Label** | Optional | **Evaluation-only** label from benchmark | `0` or `1` |

#### Example Kafka Message Payload:
```json
{
  "transaction_id": "TX-2987000",
  "card_id": "CARD-13926",
  "user_id": "USER042",
  "amount": 125.50,
  "event_time": 1791212210000,
  "merchant_id": "M-W",
  "device_type": "mobile",
  "country": "US",
  "dataset_source": "ieee_cis",
  "is_fraud": 0
}
```

### 4.2 Topic: `fraud-features` (Flink Real-Time Feature Sink)

- **Topic Name:** `fraud-features`
- **Partition Count:** 6
- **Message Key:** `user_id` / `card_id` (UTF-8 String)
- **Message Value:** Serialized JSON containing multi-scale window aggregations and velocity metrics.

#### Feature Vector Schema:

| Field Name | Type | Tier | Description |
| :--- | :--- | :--- | :--- |
| `user_id` | String | Event Data | Entity identifier |
| `timestamp` | Long | Event Data | Current window evaluation epoch millisecond |
| `transaction_count_5m` | Integer | Processing Feature | Number of transactions in trailing 5-minute sliding window |
| `total_amount_5m` | Float | Processing Feature | Cumulative spend in trailing 5-minute window |
| `average_amount_5m` | Float | Processing Feature | Mean transaction amount in 5-minute window |
| `transaction_count_10m` | Integer | Processing Feature | Number of transactions in trailing 10-minute window |
| `total_amount_10m` | Float | Processing Feature | Cumulative spend in trailing 10-minute window |
| `average_amount_10m` | Float | Processing Feature | Mean transaction amount in 10-minute window |
| `transaction_velocity_ratio` | Float | Processing Feature | Ratio: $\frac{\text{count\_5m}}{\text{count\_10m}}$ (burst indicator) |
| `amount_velocity_ratio` | Float | Processing Feature | Ratio: $\frac{\text{amount\_5m}}{\text{amount\_10m}}$ |
| `amount_bucket` | String | Processing Feature | Spending tier: `LOW`, `MEDIUM`, `HIGH`, `VERY_HIGH` |

#### Example Kafka Feature Payload:
```json
{
  "user_id": "USER042",
  "timestamp": 1791212510000,
  "transaction_count_5m": 4,
  "total_amount_5m": 450.00,
  "average_amount_5m": 112.50,
  "transaction_count_10m": 5,
  "total_amount_10m": 520.00,
  "average_amount_10m": 104.00,
  "transaction_velocity_ratio": 0.80,
  "amount_velocity_ratio": 0.865,
  "amount_bucket": "MEDIUM"
}
```

## 5. Spark Processing Data Contracts

### 5.1 PySpark Structured Streaming Ingestion Schema
```python
from pyspark.sql.types import (
    DoubleType,
    IntegerType,
    LongType,
    StringType,
    StructField,
    StructType,
)

spark_ingest_schema = StructType(
    [
        StructField("transaction_id", StringType(), False),
        StructField("card_id", StringType(), False),
        StructField("user_id", StringType(), True),
        StructField("amount", DoubleType(), False),
        StructField("event_time", LongType(), False),
        StructField("merchant_id", StringType(), True),
        StructField("device_type", StringType(), True),
        StructField("country", StringType(), True),
        StructField("is_fraud", IntegerType(), True),  # Ground-truth evaluation only
    ]
)
```

### 5.2 Spark Batch Feature Store (Parquet Data Lake) Contract
- **Storage Format:** Snappy-compressed columnar Parquet
- **Partitioning Column:** `card_id`
- **Output Columns:**
  - Base fields: `TransactionID`, `TransactionDT`, `TransactionAmt`, `ProductCD`, `card1-card6`, `addr1-2`
  - Window features:
    - `card_transaction_count_before`: Count of historical transactions for card
    - `card_amount_sum_before`: Cumulative historical spend
    - `card_amount_mean_before`: Historical average transaction size
    - `card_amount_max_before`: Historical maximum transaction size
    - `time_since_previous_transaction`: Inter-arrival seconds between transactions

## 6. Model Serving & Decision Contract

### 6.1 Input to Canonical Research Scorer (Phase 1 LightGBM E1)
- **Model Checkpoint:** `experiments/E1_lightgbm/model.txt`
- **Preprocessor:** `experiments/E1_lightgbm/preprocessing.joblib`
- **Input Dimension:** Exactly 406 features matching `feature_names.json`.
- **Note:** Real-time velocity ratios are **not** present in the 406 IEEE-CIS training features. They serve as supplementary CEP rule features or inputs for future experimental models.

### 6.2 Output Decision Contract

| Output Attribute | Type | Tier | Description | Example |
| :--- | :--- | :--- | :--- | :--- |
| `transaction_id` | String | Event Data | Transaction ID | `"TX-2987000"` |
| `fraud_probability` | Float | Inference Output | Calibrated model prediction $\in [0.0, 1.0]$ | `0.7421` |
| `threshold_applied` | Float | Inference Output | Canonical threshold | `0.616521` |
| `decision` | String | Inference Output | Transaction verdict | `"BLOCKED"` or `"APPROVED"` |
| `reasons` | List[String] | Inference Output | Rule or threshold violation codes | `["MODEL_SCORE_EXCEEDS_THRESHOLD", "HIGH_VELOCITY_BURST"]` |
| `latency_ms` | Float | Inference Output | End-to-end scoring duration | `4.2` |
