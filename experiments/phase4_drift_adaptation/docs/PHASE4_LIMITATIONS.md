# PHASE 4 LIMITATIONS

**Protocol version:** 1.1
**Date:** 2026-09-19

This document collects all scope limitations, methodological caveats,
and open questions that are deliberately out of scope for Phase 4 primary
experiment but are relevant for future work.

---

## 1. Dataset Limitations

### 1.1 BAF is synthetic
BAF (Bank Account Fraud) is a privacy-preserving synthetic dataset.
Its distributional properties (including the specific features, drift
patterns, and class imbalance) were generated by a simulator rather than
observed in production. Findings cannot be directly extrapolated to real
financial fraud datasets.

### 1.2 Eight temporal periods only
BAF provides eight monthly snapshots. With only 8 periods, the
long-term adaptation behaviour of the model (beyond a two-event
adaptation path) cannot be studied.

### 1.3 Declining sample sizes
Month 7 has 96,843 rows vs Month 0's 132,440 — a 27% reduction.
This reduces statistical power for the final evaluation period.

### 1.4 No entity tracking
Transactions are treated as independent observations. Cardholder or
account-level temporal patterns are not modelled.

---

## 2. Modelling Limitations

### 2.1 Single base model (LightGBM)
The experiment tests whether LightGBM benefits from adaptive retraining.
Whether the finding generalises to neural networks, logistic regression,
or other model families is unknown.

### 2.2 Single random seed
All models use seed=42. Cross-seed variance is not estimated, which means
the confidence interval reflects sampling variation in the data but not
variation in the model initialisation.

### 2.3 Fixed hyperparameters
Hyperparameters were locked to the E1 Phase 1 configuration for protocol
integrity. It is possible that differently tuned models would show
different adaptation benefits.

---

## 3. Drift Detection Limitations

### 3.1 Single detector (PSI only)
Only PSI was used as the drift trigger. The following detectors were
considered and deliberately excluded from the primary experiment:
- KS test (secondary diagnostic only, not trigger)
- Jensen-Shannon divergence
- Page-Hinkley (streaming)
- ADWIN (requires label feedback)

How these alternatives compare in trigger sensitivity and false-alarm
rate is not established.

### 3.2 Fixed PSI threshold (0.10) and trigger count (6/29)
These values were pre-specified per industry convention. The sensitivity
of the adaptation benefit to alternative thresholds (e.g., PSI ≥ 0.05
with 10/29, or PSI ≥ 0.25 with 3/29) was not tested.

### 3.3 `prev_address_months_count` dominates PSI
This single feature has a PSI of ~19 in both monitoring windows, far
exceeding all others. Whether the adaptive model's improvement is
primarily driven by learning the shift in this feature — rather than a
broad distributional adaptation — is not independently assessed.

---

## 4. Evaluation Limitations

### 4.1 Month 6 result is inconclusive
At Month 6, Δ PR-AUC = +0.0068 with 95% CI [−0.002, +0.016], which
crosses zero. The adaptive advantage after one retraining event is not
statistically reliable.

### 4.2 Only PR-AUC tested for statistical significance
The bootstrap test was applied to PR-AUC only (the primary protocol
metric). Other metrics (ROC-AUC, Recall@FPR, P@K) are reported
descriptively but not tested for statistical significance.

### 4.3 No multiple-comparison correction
Each evaluation period (Month 6, Month 7) is treated as a separate
primary test. No Bonferroni or other correction was applied. The Month 7
result should be interpreted in this context.

---

## 5. Adaptation Policy Limitations

### 5.1 Expanding window only
Only the expanding-window policy was tested: each retraining adds all
available historical data. Sliding-window retraining (using only recent
months) was not tested and might perform differently under concept drift.

### 5.2 Two monitoring windows only
The protocol allows at most two adaptation events (Month 5 and Month 6).
Longer-horizon adaptation over many more drift events is not captured.

### 5.3 No drift severity scaling
The same retraining policy (retrain on all available data) applies
regardless of whether 6/29 or 28/29 features are drifting. Graduated
responses to drift severity were not explored.

---

## 6. Production Generalisability

### 6.1 No streaming infrastructure
This experiment is batch-only. Real-time detection using Kafka, Spark
Streaming, or similar is explicitly out of scope for Phase 4.

### 6.2 No deployment latency
In production, model retraining takes time. The protocol assumes
retraining completes before the next evaluation period is scored.
Real-world retraining latency is not modelled.

### 6.3 BAF variant comparison
Only BAF Base was used. BAF Variant I–V (which introduce controlled
bias and fairness scenarios) were not included. Cross-variant
generalisability of adaptation benefits is unknown.
